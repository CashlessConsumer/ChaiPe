3. Versioning Scheme

Semantic Versioning (SemVer)

ChaiPe follows Semantic Versioning 2.0.0. Version numbers follow the format MAJOR.MINOR.PATCH.

MAJOR

Incompatible API changes or major feature additions that may require migration

MINOR

New features added in a backwards-compatible manner

PATCH

Backwards-compatible bug fixes and improvements

What Constitutes Breaking Changes?

  • Removal or renaming of public API methods
  • Changes to method signatures (parameters, return types)
  • Changes to configuration object structure
  • Removal of themes or features
  • Changes to event callback signatures
  • Changes to default behavior that affect existing implementations

What Constitutes Minor Updates?

  • Addition of new API methods
  • Addition of new configuration options
  • Addition of new themes
  • Addition of new event callbacks
  • New features that don't break existing functionality

What Constitutes Patch Updates?

  • Bug fixes
  • Performance improvements
  • Documentation updates
  • Internal refactoring
  • Security fixes

Pre-release Identifiers: Pre-release versions may include identifiers like -alpha, -beta, or -rc (e.g., v1.0.0-beta.1). These are not stable releases and may contain bugs or incomplete features.

Using CDN

Update the CDN link in your HTML:

Breaking Change Migrations

Current Version (v1.0.0): No breaking changes from previous versions as this is the first stable release.

Future Migration Guide (Template)

▼

When breaking changes are introduced in future versions, migration instructions will be provided here.

Example Migration:

// Old way (v1.x)
ChaiPe.init({
    upiId: 'example@upi',
    amounts: [10, 20, 50]
});

// New way (v2.x)
ChaiPe.init({
    payment: {
        upiId: 'example@upi',
        amounts: [10, 20, 50]
    }
});

Configuration Changes

When upgrading between minor versions, review the configuration options:

  • New configuration options are added with sensible defaults
  • Deprecated options will be marked in documentation
  • Removed options will be documented in release notes

Deprecation Notices

Current Deprecations: None

Best Practice: Always test upgrades in a development environment before deploying to production. Review the release notes carefully for any changes that might affect your implementation.

6. Security Advisories

Current Status: No known security vulnerabilities in the latest release (v1.0.0).

Security Vulnerability Reporting

If you discover a security vulnerability, please report it responsibly:

  • Do not create a public GitHub issue
  • Use GitHub's Private Vulnerability Reporting
  • Email: security@chaipe.dev
  • Provide detailed information about the vulnerability
  • Include steps to reproduce (if possible)

Security Update Process

When a security vulnerability is reported:

  1. We will acknowledge receipt within 48 hours
  2. We will investigate and assess the severity
  3. We will develop a fix in a private branch
  4. We will coordinate disclosure with the reporter
  5. We will release a security update as soon as possible
  6. We will publish a security advisory with details

CVE Information

Current CVEs: None

Security vulnerabilities will be assigned CVE numbers when applicable. Check our Security Advisories page for the latest information.

Best Practices for Security

To ensure secure implementation of ChaiPe:

  • Always use HTTPS on your website
  • Keep ChaiPe updated to the latest version
  • Validate and sanitize any user-provided data
  • Implement proper authentication on your backend
  • Use Content Security Policy (CSP) headers
  • Regularly audit your website for vulnerabilities
  • Monitor for unusual payment activity

Important: ChaiPe is a frontend library. Security of your website and backend infrastructure is your responsibility. Follow web security best practices to protect your users and their data.
